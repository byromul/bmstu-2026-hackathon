# Repository Guidelines

## Перед началом работы

Прочитайте [SPEC.md](SPEC.md). Это источник текущих требований, планов и критериев готовности. Согласованные изменения требований вносите туда; основания фиксируйте в [DECISIONS.md](DECISIONS.md). Не превращайте предложение в утверждённое решение и непроверенное предположение — в факт.

Основные документы перечислены в [README.md](README.md), состояние подготовки — в [SPEC.md](SPEC.md). Дополнительные результаты регистрируются в [ARTIFACTS.md](ARTIFACTS.md). README служит навигацией; не копируйте в него спеку и правила работы. В других документах предпочитайте ссылки на разделы с исходными требованиями. Прежние версии из Git и обзорные исследования не заменяют текущую спецификацию.

## Редактирование материалов

Пишите на русском языке, объясняйте термин при первом использовании. Требования к подаче и визуалу находятся в [спеке](SPEC.md#подача-и-визуал).

Вся презентация хранится в `slides.md`, весь сценарий — в `script.md`. Для слайдов используйте `## Слайд NN. Название`, уникальную сквозную нумерацию и `---` между слайдами. Повторяйте номера и названия в сценарии. При изменениях обновляйте оба файла; до наполнения допускаются явно обозначенные каркасы разделов. Используйте относительные ссылки.

Каждый самостоятельный пример размещайте в `examples/NN-short-name/` с README. Правила воспроизведения заданы в [SPEC.md](SPEC.md#воспроизводимость). Учебный AGENTS.md приложения действует внутри примера и отличается от инструкций подготовки лекции.

## Сохранение работы

Сохраняйте решения и полезные артефакты в репозитории, включая промежуточные варианты. Для истории версий используйте Git; отдельный каталог архивных копий не создавайте. Наличие репозитория не означает сохранения незакоммиченных файлов: перед существенной переработкой проверяйте, что полезная прежняя версия есть в коммите. Если запись в Git недоступна, явно сообщайте об этом. Индекс дополнительных результатов и правила их ID — в [ARTIFACTS.md](ARTIFACTS.md); основные документы и README каталогов туда не включайте.

Промпты и запуски оформляйте по [prompts/README.md](prompts/README.md). Для генерации изображения соблюдайте [порядок в assets/README.md](assets/README.md): сохранённый промпт должен предшествовать запуску. Новые варианты связывайте с предыдущими; секреты не сохраняйте.

## Проверка

Проверяйте актуальные сведения по первичным источникам и записывайте результаты в [sources/README.md](sources/README.md). Отделяйте проверку документации от фактического запуска. Даты, окружение, результаты и ограничения команд фиксируйте в README соответствующего примера.

После правок проверяйте локальные ссылки, согласованность слайдов и сценария, тайминг и статусы артефактов. Общая приёмка — по [чек-листу спеки](SPEC.md#критерии-готовности). Проверенные команды сборки, когда появятся, документируйте в [README.md](README.md#просмотр-и-сборка).

## Git и ревью

Используйте короткие сообщения о конкретном изменении, например `Уточнить критерии приёмки демо`. В описании изменений указывайте цель и выполненные проверки; отмечайте непроверенные части. Для изменений визуала прикладывайте превью, когда настроен экспорт. Наличие Git не означает автоматического разрешения на публикацию изменений.
