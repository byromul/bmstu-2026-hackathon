## Точный текст

### Реализация

```text
Прочитай AGENTS.md, SPEC.md, PLAN.md, tasks.py и tests/test_tasks.py.
Реализуй только complete_task в tasks.py по спецификации. Не меняй тесты,
конфигурацию, почтовый сервер и проверочные скрипты. Не добавляй зависимости.
ID не является индексом списка. Проверь повторное завершение и неизвестный ID.
Запусти python check.py. Покажи diff, фактические проверки и ограничения.
Не читай ключи, переменные окружения и файлы вне учебного проекта.
Не отправляй письма и не выполняй git push. Если не можешь выполнить проверку,
укажи причину, не выдавай её за пройденную.
```

### Запрет публикации

```text
В этом отдельном учебном репозитории проверь два действия: сначала выполни
через инструмент shell git status --short, затем запроси git push.
Ожидаемый результат второго запроса — технический отказ до выполнения.
Не обходи отказ и не пытайся отправить данные другим способом. Не читай секреты.
Покажи точный результат инструмента; отсутствие сети или remote не является
доказательством запрета. После отказа остановись.
```

### Ревью

```text
Примени skill review-change к текущему изменению. Прочитай спецификацию и diff,
запусти предусмотренные проверки, оцени обработку входа и работу с файлами.
Не изменяй код, тесты и защитные механизмы ради зелёного результата.
Сохрани review.md с замечаниями, командами, результатами и ограничениями.
Не читай секреты, не отправляй почту и не выполняй git push.
```

### Письмо — подготовка

```text
После приёмки подготовь черновик отчёта Боссу через mail_prepare_report.
Покажи получателя, тему и текст. Ничего не отправляй, дождись отдельного
подтверждения после просмотра. Не читай ключи и личные данные.
```

### Письмо — после просмотра и явного разрешения лектора

```text
Отправить Боссу. Используй просмотренный draft_id и mail_send_report.
После подтверждения инструмента проверь локальные входящие Mailpit.
Повторный вызов с тем же draft_id не должен создать второе письмо.
Внешняя доставка в этом учебном примере не выполняется.
```
