# Визуальные материалы

Здесь хранятся оформление, вспомогательные файлы и превью презентации. Схемы первых десяти слайдов заданы редактируемыми HTML-блоками в `slides.md`; генерация изображений для них не использовалась. Материалы конкретных практических демонстраций храните вместе с примером в `examples/`.

- Используйте понятные имена: `agent-loop.svg`, `assistant-agent-comparison.png`.
- Подключайте файлы относительными ссылками из `slides.md`.
- Сохраняйте редактируемые исходники схем, когда они доступны.
- Проверяйте читаемость подписей и контраст в средстве показа.
- Для сторонних материалов фиксируйте источник и условия использования в [sources/README.md](../sources/README.md).
- Удаляйте ключи, персональные данные и другие секреты со скриншотов.

## Оформление и превью

- [deck.css](deck.css) — светлая тема, системные шрифты, схемы и таблицы; базовый кадр 1600 × 900.
- [deck.js](deck.js) — навигация и показ сценария. Оба файла встраиваются сборщиком в итоговый HTML.
- [preview/index.html](preview/index.html) — галерея первых десяти слайдов; PNG сняты с HTML в Chrome. Это снимок текущего драфта, после изменений его нужно обновить.
- [test_build.py](test_build.py) — проверки конвертора. Команды запуска — в [README](../README.md#просмотр-и-сборка).

## Формат слайдов

Конвертор поддерживает используемое в проекте подмножество Markdown: абзацы, заголовки, **жирный текст**, строчный код, ссылки, локальные изображения, простые списки, таблицы, цитаты и блоки кода. Вложенные списки и расширения вроде Mermaid не обрабатываются. Схемы можно задавать обычным HTML с классами из `deck.css`.

Сразу после заголовка слайда укажите макет и непрерывный интервал от начала лекции:

```md
## Слайд 01. Название
<!-- layout: cover; time: 00:00–00:40 -->
```

Доступные макеты первого драфта: `cover`, `code`, `cycle`, `model`, `context`, `compare`, `harness`, `layers`, `access`, `options`. Для обычного слайда можно использовать `plain`; новый макет оформляйте в CSS. Заголовок в сценарии должен совпадать. Строка `Источники: [Название](URL)` переносится в нижнюю часть слайда; повтор внешнего URL останавливает сборку. Разделы без заголовка `Слайд NN` остаются каркасами и не попадают в HTML.

Изображения подключайте локально: `![Описание](assets/имя.png)`. Сборщик встраивает их в HTML. Не добавляйте CDN, веб-шрифты, внешние скрипты или сетевые ресурсы в CSS. HTML-блоки предназначены для доверенных материалов этого репозитория.

## Порядок генерации изображений

1. Выделите следующий свободный ID в [индексе артефактов](../ARTIFACTS.md), в формате `ART-NNNN` (здесь NNNN — заполнитель, а не номер для повторного использования). Добавьте запись со статусом «подготовка»; до создания результата укажите планируемое имя файла без ссылки.
2. Составьте эффективный промпт: учебная цель, объекты и связи, композиция, стиль, текст на изображении, соотношение сторон, фон и ограничения. Сохраните точный текст в `prompts/ART-NNNN-short-name-v01.md` **до запуска** и добавьте ссылку на него в индекс. Требования к записи приведены в [prompts/README.md](../prompts/README.md).
3. Выполните сохранённый промпт. Зафиксируйте инструмент, модель и доступные параметры, фактическую дату запуска и использованные референсы. Если инструмент недоступен, оставьте статус «подготовка» и запишите причину.
4. Сохраните полученный файл в `assets/ART-NNNN-short-name-v01.png` (расширение должно соответствовать фактическому формату). Не ограничивайтесь временной ссылкой сервиса.
5. Проверьте результат и обновите индекс: ID, ссылка на промпт, название и ссылка на файл, описание, статус и связь с исходным вариантом. Укажите ограничения или дефекты, если они есть.
6. Для нового варианта используйте новый ID и отдельный файл. Сохраняйте точный промпт каждого запуска; неизменённый промпт можно использовать повторно по ссылке. Предыдущие полезные варианты не удаляйте и не перезаписывайте.

Перед работой учитывайте [требования к визуалу](../SPEC.md#подача-и-визуал). Приведённые имена — примеры соглашения; эти изображения ещё не созданы. Сгенерированные иллюстрации сохраняйте здесь; записи выполнения учебных демонстраций остаются в `examples/` и также регистрируются в общем индексе.
