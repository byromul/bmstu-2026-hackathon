# Визуальные материалы

Здесь хранятся оформление, вспомогательные файлы и превью презентации. Схемы теоретической части заданы смысловыми блоками в `slides.md`; восемь используемых схем экспортированы в SVG через локальный Excalidraw SDK; ещё две сохранены как предыдущий вариант. Два снимка практики получены из работающих интерфейсов,, остальные элементы создаёт модуль HTML/CSS. Модель генерации изображений не используется. Порядок перегенерации — в [README Excalidraw](excalidraw/README.md). Материалы конкретных практических демонстраций храните вместе с примером в `examples/`.

- Используйте понятные имена: `agent-loop.svg`, `assistant-agent-comparison.png`.
- Подключайте изображения в `slides.md` через ID из ARTIFACTS.md; формат описан ниже.
- Сохраняйте редактируемые исходники схем, когда они доступны.
- Проверяйте читаемость подписей и контраст в средстве показа.
- Для сторонних материалов фиксируйте источник и условия использования в [sources/README.md](../sources/README.md).
- Удаляйте ключи, персональные данные и другие секреты со скриншотов.

## Оформление и превью

- [deck.css](deck.css) — светлая тема, системные шрифты, схемы и таблицы; базовый кадр 1600 × 900.
- [render_elements.py](render_elements.py) — отрисовка смысловых блоков и разрешение ID изображений через реестр.
- [deck.js](deck.js) — навигация и показ сценария. Оба файла встраиваются сборщиком в итоговый HTML.
- [preview/index.html](preview/index.html) — галерея всех 50 слайдов; PNG сняты с HTML в Chrome. Это снимок текущего драфта, после изменений его нужно обновить.
- [test_build.py](test_build.py) — проверки конвертора. Команды запуска — в [README](../README.md#просмотр-и-сборка).

## Формат слайдов

Содержание и пожелания автора хранятся в Markdown, конкретное оформление — в `render_elements.py` и `deck.css`. HTML в исходнике запрещён. Обычный Markdown используется для текста, кода, простых списков, цитат и ссылок. Вложенные списки не поддерживаются.

### Метаданные слайда

После заголовка `## Слайд NN. Название` добавьте именованный блок с JSON. Заголовки слайда и сценария должны совпадать, интервалы времени идут непрерывно внутри каждого блока. Поле `block` (1 или 2) обозначает блок; при переходе к блоку 2 время начинается с 00:00. Пример:

```slide
{
  "layout": "plain",
  "time": "00:00–00:40",
  "author": {
    "intent": "Объяснить одну основную мысль",
    "appearance": "Светлый фон; главный вывод крупнее пояснений",
    "must": ["Не обрезать подписи"]
  }
}
```

Необязательное поле `footer_note` блока `slide` переносит дату или служебное пояснение в нижнюю часть слайда мелким шрифтом.

`author` хранит указания дизайнеру или агенту, а не текст для показа. Конвертор не интерпретирует произвольный русский текст как CSS: автоматическое оформление задаётся поддерживаемыми параметрами ниже. При изменении дизайна нужно сверяться с `author`; содержимое этих полей в HTML не попадает.

Макеты: `plain`, `cover`, `code`, `cycle`, `model`, `context`, `compare`, `harness`, `layers`, `access`, `options`, `agent-loop`, `sdlc-visual`, `llm-visual`, `harness-visual`. Новые макеты добавляются в CSS. Каркасные разделы без `Слайд NN` не собираются.

### Диаграммы, таблицы и акценты

Именованные блоки `diagram`, `table`, `callout`, `image`, `cover`, `result`, `caption` содержат JSON, а не HTML. Все поддерживают поле `author`.

```diagram
{
  "kind": "flows",
  "render": "native",
  "rows": [{
    "title": "Один шаг агента",
    "nodes": [{"text": "Модель", "accent": true}, {"text": "Инструмент"}],
    "return": "Результат возвращается модели"
  }],
  "author": {"appearance": "Горизонтальный поток; обратную связь показать отдельной стрелкой"}
}
```

Виды схем: `cycle` — шесть этапов в порядке процесса; `flows` — ряды последовательностей; `context` — отбор контекста; `harness` — управляющий цикл; `layers` — независимые компоненты. Рабочие образцы всех пяти видов находятся в [slides.md](../slides.md). `accent: true` выделяет узел, `return` задаёт подпись обратной связи.

```table
{
  "columns": ["Приложение / компания", "Условие"],
  "rows": [["Название / Компания", "Проверенное условие доступа"]],
  "emphasize": [0],
  "author": {"appearance": "Выделить первый столбец; без вертикальных линий"}
}
```

`emphasize` содержит индексы выделяемых столбцов, начиная с нуля. `callout` принимает `text` и `tone`: `key` для главного вывода, `warning` для существенного ограничения. Акцент задаётся размером, насыщенностью, фоном и полосой слева. `caption` принимает `text`; примеры остальных блоков — в исходнике презентации.

У `diagram` и `table` можно заменить `render: "native"` на `render: "image"`, добавить `artifact` и `alt`. Исходные данные сохраняются, но на слайде используется готовое изображение. Это позволяет сменить представление без переписывания содержания. Mermaid пока не подключён: его блок вызывает явную ошибку, а не выводится как код; сетевых загрузок движка нет.

### Изображения через реестр

Используйте `![Описание](artifact:ART-NNNN)` или блок `image`:

```image
{
  "artifact": "ART-NNNN",
  "alt": "Полное описание изображения",
  "fit": "contain",
  "author": {"appearance": "Сохранить все подписи; не обрезать края"}
}
```

`ART-NNNN` здесь заполнитель: замените его выданным ID. `fit` принимает `contain` (целиком) или `cover` (с обрезкой). Для схем предпочтителен `contain`.

В строке этого ID в [ARTIFACTS.md](../ARTIFACTS.md) столбец «Промпт» должен ссылаться на сохранённый локальный промпт, а столбец файла — ровно на одно изображение PNG, JPEG, WebP или SVG. Пути считаются от реестра. Сборка проверяет наличие записи, промпта и картинки, затем встраивает картинку в HTML. Генерация выполняется заранее по процедуре ниже; сборщик не вызывает модели. Прямые пути к картинкам в `slides.md` не допускаются. Для сторонних материалов сохраняйте описание поиска/подготовки и происхождение, не приписывая им генерацию ИИ.

### Ссылки и автономность

`Источники: [Название](URL)` размещает ссылки внизу слайда; повтор внешнего URL останавливает сборку. В презентации остаются внешние ссылки и якоря внутри неё. Ссылки на локальные документы и код, в том числе в сценарии, превращаются в текст без `href`. Поэтому HTML можно переносить отдельно от репозитория.

Не добавляйте CDN, веб-шрифты, внешние скрипты или сетевые ресурсы в CSS. Изменение оформления не должно создавать зависимость от сети.

## Порядок генерации изображений

1. Выделите следующий свободный ID в [индексе артефактов](../ARTIFACTS.md), в формате `ART-NNNN` (здесь NNNN — заполнитель, а не номер для повторного использования). Добавьте запись со статусом «подготовка»; до создания результата укажите планируемое имя файла без ссылки.
2. Составьте эффективный промпт: учебная цель, объекты и связи, композиция, стиль, текст на изображении, соотношение сторон, фон и ограничения. Сохраните точный текст в `prompts/ART-NNNN-short-name-v01.md` **до запуска** и добавьте ссылку на него в индекс. Требования к записи приведены в [prompts/README.md](../prompts/README.md).
3. Выполните сохранённый промпт. Зафиксируйте инструмент, модель и доступные параметры, фактическую дату запуска и использованные референсы. Если инструмент недоступен, оставьте статус «подготовка» и запишите причину.
4. Сохраните полученный файл в `assets/ART-NNNN-short-name-v01.png` (расширение должно соответствовать фактическому формату). Не ограничивайтесь временной ссылкой сервиса.
5. Проверьте результат и обновите индекс: ID, ссылка на промпт, название и ссылка на файл, описание, статус и связь с исходным вариантом. Укажите ограничения или дефекты, если они есть.
6. Для нового варианта используйте новый ID и отдельный файл. Сохраняйте точный промпт каждого запуска; неизменённый промпт можно использовать повторно по ссылке. Предыдущие полезные варианты не удаляйте и не перезаписывайте.

Перед работой учитывайте [требования к визуалу](../SPEC.md#подача-и-визуал). Приведённые имена — примеры соглашения; эти изображения ещё не созданы. Сгенерированные иллюстрации сохраняйте здесь; записи выполнения учебных демонстраций остаются в `examples/` и также регистрируются в общем индексе.

## Обновление превью

После сборки HTML запустите из корня репозитория:

```sh
node assets/verify-deck.mjs
```

Нужны Node.js и Google Chrome; при нестандартном пути задайте `CHROME_BIN`. Скрипт использует отдельный временный профиль, отключает сеть, снимает все слайды текущего HTML в `assets/preview/`, проверяет загрузку изображений, размещение и клавишу N. При ошибке возвращает ненулевой код. Отчёт сохраняется в `assets/preview/report.json`. Для отдельных HTML можно передать имя: `node assets/verify-deck.mjs lecture-theory.html` или `node assets/verify-deck.mjs lecture-practice.html`; они проверяются во временном каталоге и не заменяют общую галерею. Сейчас проверяются все 50 слайдов: 36 теоретических и 14 практических. Галерея index.html обновляется автоматически. Обычная сборка HTML от этого инструмента не зависит.

## Учебный комплект в автономном HTML

`python3 assets/package_materials.py` создаёт [lecture-materials.zip](../lecture-materials.zip) по явному списку FILES. Ссылка `[Материалы](lecture-materials.zip)` в slides.md или script.md встраивает тот же ZIP прямо в HTML как скачиваемый файл. Поэтому полный и оба отдельных блока работают без каталога репозитория. Другие локальные ссылки остаются текстом.

В комплекте START-HERE.md, полный учебный промпт, исходники практики с README и сравнение токенов. Ссылки на не включённые документы подготовки преобразуются в текст. Файлы .lab, ключи, окружения и сырые журналы не копируются. Список файлов фиксирован, ZIP воспроизводим при одинаковых входах; готовый комплект нужно обновлять после изменения исходников.

verify-deck.mjs проверяет скачивание в Chrome без сети и сравнивает байты с архивом внутри HTML. Тест конвертора открывает ZIP и проверяет наличие инструкции, промпта и файлов проекта.
