# Ревью подготовки учебного примера

Дата: 2026-11-08. Автор: Codex при подготовке материалов; это не ручное ревью лектора и не репетиция аудитории.

## Принятое поведение

Опорная реализация лектора в tasks.py ищет объект по целому ID, изменяет только его, безопасна при повторе и даёт KeyError для отсутствующего ID. HTTP переводит отсутствие ID 0/999 в 404 без изменения файла. Состояние сохраняется после перезапуска. Заголовки задач экранируются для HTML. Результаты: [13 тестов, Ruff и Bandit](reports/checks.json), [HTTP/MCP/SMTP](reports/integration.json).

Намеренный дефект tasks[id] обнаружен тестами: [bug-checks](reports/bug-checks.json). Успех линтеров на этом дефекте показывает, почему они не заменяют проверку требований.

## Работа модели и вмешательства

GLM-4.5-Flash изменила функцию в отдельном start-проекте и применила review-change. Тест поймал bool ID; после повторов одинаковой правки агенту дано уточнение ART-0045. Независимая приёмка затем нашла неизвестный ID 0, пропущенный зелёными тестами и ревью. Лектор добавил случай в существующий тест, агент исправил код по ART-0046. Этот вклад не выдаётся за полностью автономный успех. [Журнал](reports/model-check.md), [правка](reports/agent-change.patch).

В [сыром ревью модели](reports/agent-review.md) фраза «Bandit: 0 уязвимостей» означает лишь отсутствие находок этого запуска. Полная защищённость не установлена. Заголовок X-Demo-Action усложняет простой межсайтовый POST, но не заменяет полноценную модель защиты и авторизацию. Обработка NotImplementedError в app.py нужна для учебного состояния start; её не следует удалять как «устаревшую» по совету модели. Зависимости отсутствуют у самого приложения, но есть у MCP и проверок.

## Границы и решения о приёмке

Это локальный однопользовательский пример на синтетических данных. Авторизация, многопользовательская конкуренция, нагрузка, полный сетевой аудит, установка Windows и изоляция ОС не проверены. Правило edit ограничивает прямой инструмент, а подтверждённая shell-команда может иметь более широкие эффекты: просмотр команды человеком остаётся необходимым. Regex хука блокирует испытанные git push, но не все способы передачи данных. Файл checks.json связывает отчёт с хешами, не является криптографическим доверием к владельцу файлов.

Письмо модели принято локальным Mailpit после подтверждения конкретного черновика. Повтор того же draft_id не создал нового письма; внешняя доставка не выполнялась. Зелёные проверки разрешают готовить отчёт по наблюдаемым критериям, но не обещать отсутствие всех ошибок. Перед лекцией нужны свежий прогон модели и репетиция всего блока за 40 минут.
