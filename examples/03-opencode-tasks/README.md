# Практика OpenCode: завершение задачи по ID

Учебный пример ART-0034 для слайдов 37–50. Лектор выполняет команды, аудитория наблюдает. Одна новая функция: отметить выбранную задачу выполненной. [Требования](SPEC.md), [план](PLAN.md), [правила приложения](AGENTS.md), [задания агенту](../../prompts/ART-0035-practice-tasks-v01.md).

## Окружение и статус

Проверка 2026-11-08: macOS arm64, Python 3.14.7, OpenCode **2.2.6**, Node **v26.9.0**, Mailpit **1.33.1**, MCP Python SDK **1.26.0**, Ruff **0.17.4**, Bandit **1.9.4**. Зависимости зафиксированы в [requirements-lock.txt](requirements-lock.txt). Для повторения нужен Python 3.10+; весь набор версий фактически проверен только на Python 3.14.7 и macOS.

Приложение работает на стандартной библиотеке. Зависимости нужны для MCP и проверок. Почта принимается локальным Mailpit: **внешняя доставка не выполняется**, пересылка наружу не настраивается. Адрес `boss@example.test` вымышленный.

Исходный драфт конфигурации V1 сохранён в Git-коммите `ec20fb1`. Пользователь обновил OpenCode; текущий пример использует нативные `permissions`, `providers`, `mcp.servers` и plugin API V2. Не копируйте поля V1 `permission` / `bash` в этот вариант. Работающий сервис OpenCode пользователя не изменялся: используется `--standalone`.

## Установка до занятия

Скачайте [Python](https://www.python.org/downloads/), [Git](https://git-scm.com/downloads), CLI из [выпуска OpenCode 2.2.6](https://github.com/anomalyco/opencode/releases/tag/v2.2.6) и готовый файл [Mailpit 1.33.1](https://github.com/axllent/mailpit/releases/tag/v1.33.1) для своей ОС и архитектуры. Добавьте исполняемые файлы в PATH либо используйте полный путь. Установки Python/Git/OpenCode не повторялись в этой сессии; это инструкции по официальным страницам. Пользователь самостоятельно обновил OpenCode до V2.

На macOS использованы zsh и Terminal. Перейдите **в корень репозитория лекции**, затем:

```sh
python3 -m venv examples/03-opencode-tasks/.venv
examples/03-opencode-tasks/.venv/bin/python -m pip install -r examples/03-opencode-tasks/requirements-lock.txt
opencode --version
mailpit version
```

Ожидаются OpenCode 2.2.6 и Mailpit 1.33.1. Команда `mailpit --version` не поддерживается. `mailpit version` может дополнительно проверить обновление по сети; ошибку этой проверки отличайте от версии установленного файла.

На Windows используйте PowerShell; из того же корня:

```powershell
py -m venv examples/03-opencode-tasks/.venv
.\examples\03-opencode-tasks\.venv\Scripts\python.exe -m pip install -r examples/03-opencode-tasks/requirements-lock.txt
opencode --version
mailpit version
```

Для OpenCode V2 на Windows официальный сайт предлагает готовый CLI-файл; не переносите старые советы о пакетных менеджерах V1. Windows в этой сессии не запускался. Зависимости устанавливались в отдельное временное окружение; путь `.venv` выше — эквивалентный вариант для повторения. Виртуальное окружение и рабочие данные исключены из Git.

## Доступ к модели

Используется **GLM-4.5-Flash через официальный Z.ai API**, `https://api.z.ai/api/paas/v4`. Официальный прайс на дату проверки отмечает модель как бесплатную; универсальная квота для всех участников не установлена. Нужен собственный аккаунт и ключ, подходящий для стандартного API. [Проверка модели и ограничения](reports/model-check.md).

Пользователь указал файл `~/.glm_token`. Запишите ключ в такой локальный файл средствами своего редактора; не вставляйте его в команду, промпт, Git или чат. На Windows `~` соответствует домашней папке пользователя. Другой путь задаётся параметром `--key-file` скрипта run_agent.py.

[run_agent.py](run_agent.py) читает файл только при запуске, передаёт значение через окружение дочернего OpenCode и создаёт отдельные каталоги конфигурации/данных в `.lab/opencode-user`. Значение не печатается, не записывается в opencode.json и не передаётся почтовому MCP: там переменная явно очищена. Не запускайте отладку с выводом действующего ключа; для `debug config` скрипт убирает его из окружения. Это не ОС-песочница: не давайте агенту команды, читающие окружение или личные файлы.

GLM-4.7-Flash при подготовке дважды вернула HTTP 429, код 1305, перегрузка. Публичный бесплатный маршрут OpenCode также не дал рабочий запуск. На платную модель автоматического перехода нет. Успех одной сессии GLM-4.5-Flash не гарантирует доступность и лимиты на 14 ноября: нужен повторный прогон.

## Подготовить отдельную рабочую папку

Скрипт [prepare.py](prepare.py) копирует только учебные файлы, создаёт локальный Git-репозиторий и фиксирует исходное состояние. Внешний remote не создаётся. Существующий каталог скрипт не удаляет и не перезаписывает.

Из корня лекции, macOS:

```sh
examples/03-opencode-tasks/.venv/bin/python examples/03-opencode-tasks/prepare.py /tmp/lecture-tasks-start --state start
```

Windows, PowerShell:

```powershell
.\examples\03-opencode-tasks\.venv\Scripts\python.exe examples/03-opencode-tasks/prepare.py "$env:TEMP\lecture-tasks-start" --state start
```

Состояния:

- `start`: список показывается; complete_task ещё не реализована, кнопка вернёт понятное сообщение 501, соответствующие тесты падают.
- `bug`: специально подготовленная ошибка ID/индекса. Тесты должны её обнаружить; это не случайная ошибка модели.
- `ready`: заранее подготовленный исправный результат лектора. Не выдавайте его за живую генерацию модели.

Для каждого состояния выбирайте **новую** папку. В корне этого примера находится готовая опорная реализация, а не три каталога архивных копий.

## Запустить приложение и почтовый приёмник

В первом терминале перейдите в созданную рабочую папку и запустите приложение Python из окружения подготовки. Например, macOS из корня лекции:

```sh
examples/03-opencode-tasks/.venv/bin/python /tmp/lecture-tasks-start/app.py --data /tmp/lecture-tasks-start/.lab/tasks.json
```

В команде явно указан путь файла состояния. Альтернативно перейдите в рабочую папку и запустите Python подготовленного окружения с аргументом `app.py`. Откройте `http://127.0.0.1:8080`. Завершить сервер — Ctrl+C.

Во втором терминале:

```sh
mailpit --listen 127.0.0.1:8025 --smtp 127.0.0.1:1025 --disable-version-check --smtp-disable-rdns --ignore-duplicate-ids --smtp-allowed-recipients '^boss@example\.test$'
```

В PowerShell используйте ту же строку с одинарными кавычками. Откройте `http://127.0.0.1:8025`. Порты должны быть свободны; не останавливайте чужой процесс ради примера. Флаги ограничивают адресата и прослушивание loopback; relay/forwarding не включены. На macOS Mailpit загружен из официального выпуска, SHA256 сверена с метаданными GitHub; сведения — в журнале проверки.

## Рабочая сессия OpenCode

Из корня лекции:

```sh
examples/03-opencode-tasks/.venv/bin/python examples/03-opencode-tasks/run_agent.py --project /tmp/lecture-tasks-start
```

Дождитесь загрузки проекта и MCP в этой сессии. Откройте список MCP средствами интерфейса и проверьте статус mail и три инструмента. В холодном отдельном вызове `mcp list` при подготовке был получен преждевременный ответ «No MCP servers configured»; повторный запуск команды не является доказательством подключения. Фактически соединение проверено после загрузки постоянного учебного сервера через API и завершённые модельные вызовы mail_prepare_report / mail_send_report / mail_list_inbox.

В Windows замените путь интерпретатора на `...\.venv\Scripts\python.exe`, рабочую папку на `"$env:TEMP\lecture-tasks-start"`. Скрипт добавляет `--standalone`: это отдельный сервер, который не подключается к уже работающему пользовательскому сервису. Если `opencode` находится вне PATH, задайте `--opencode /полный/путь/opencode`.

Проведите шаги в таком порядке:

1. Покажите исходное приложение, SPEC.md и PLAN.md; сохраните требования до реализации.
2. Покажите AGENTS.md и конфигурацию. В V2 список `permissions` использует эффекты allow/ask/deny. Чтение и команды проверки разрешены, редактирование ограничено tasks.py и review.md, почтовая отправка требует ask, git push запрещён.
3. Покажите подключённый MCP и журнал загрузки плагина `.lab/guard.log`. Название нативного действия V2 — `shell`, хук регистрируется через `ctx.tool.hook('execute.before', ...)`.
4. Дайте точное задание «Реализация» из ART-0035. Не включайте `--auto` и не разрешайте все действия. При долгом ожидании перейдите к явно обозначенному ready.
5. Просмотрите diff. Примените `review-change` заданием «Ревью» и проверьте фактические результаты.
6. Выполните ручную приёмку в браузере и по HTTP. После решения о приёмке дайте задание на черновик письма.
7. Проверьте адресата и текст, затем явно подтвердите «Отправить Боссу» и одобрите запрос инструмента. Проверьте письмо в Mailpit.
8. Повторный вызов с тем же draft_id должен вернуть существующее письмо, не новое. При неизвестном исходе автоматического повтора нет.

Удобный запуск из файла сообщения для записи: CLI `opencode run --format json` принимает задание аргументом; точные тексты и история запусков сохраняются в prompts и reports. Ключ не должен попадать в аргументы.

## Проверка без модели

Из каталога готового примера, в активированном окружении:

```sh
python check.py
node verify_guard.mjs
```

`check.py` запускает 13 тестов, Ruff и Bandit и сохраняет `.lab/checks.json` с хешами исходников. Подготовка письма блокируется при провале или изменении кода после проверки. Это связь отчёта с файлами, а не защита от человека, способного переписать отчёт вручную.

Проверка callback плагина отдельно отклоняет четыре варианта git push до исполнения. Её нельзя выдавать за доказательство интеграции OpenCode. Хук не является полным анализатором shell; другие способы передачи данных требуют собственных ограничений среды и сети.

Для полного HTTP + MCP + SMTP теста, когда 8080/8025/1025 не заняты просмотром:

```sh
python check.py
python integration_check.py
```

`integration_check.py` использует HTTP-порт 18080 и создаёт временную почтовую БД. На Windows и macOS можно задать путь переменной `MAILPIT_BIN` к готовому бинарному файлу; по умолчанию используется `mailpit` из PATH. В этой проверке модель не вызывается: MCP-клиент SDK реально отправляет одно учебное письмо и проверяет отсутствие дубля. [Фактический отчёт](reports/integration.json).

## Ручная приёмка и резервный показ

1. Завершите ID 1; ID 2 должен остаться не выполнен.
2. Обновите страницу и перезапустите сервер с тем же файлом `.lab/tasks.json`: результат должен сохраниться.
3. Повторите завершение ID 1; состояние не должно испортиться.
4. Для неизвестных ID 0 и 999 получите 404; файл не должен измениться. В POST нужен заголовок `X-Demo-Action: complete`; HTTP-интеграционный тест делает это автоматически.
5. Просмотрите diff и `.lab/checks.json`. Оцените риски ввода/HTML вручную. Зеленый тест не заменяет этот просмотр.
6. У письма проверьте получателя, тему, текст и фактическое появление во входящих. Не путайте это с внешней доставкой.

При задержке модели дольше 60–90 секунд переходите к новой папке `--state ready` и называйте её заранее подготовленной. Для ошибки используйте новую папку `--state bug`. Не переписывайте незакоммиченные результаты текущего запуска. Реальные агентские журналы и ручная опорная реализация учитываются отдельно; репетиция всего блока пока не проводилась.

## Порядок показа после ревью

Сценарий и отсечки времени находятся в script.md лекции, слайды 41–48. До начала подготовьте отдельные start, bug и ready. На 44 показывается реализация в start либо явно обозначенный резерв. На 45 открывается bug и остаётся дефектным. На 46 открываем заранее сохранённый skill; проверяем его отдельно в bug и ready. На 47 активны код, сервер и данные только ready; к этой же версии относится последующая почта.

Отказ модели без вызова инструмента, permissions deny и ошибка DEMO_GUARD — разные результаты. Для hook сопоставляйте запись LOADED, DENY и ошибку конкретного вызова shell. Если запрос остановился раньше, используйте сохранённый журнал как запись, не меняя разрешения. Обычный check.py на bug не подтверждает применение skill.

Резервные записи не следует приписывать новой папке: называйте происхождение и версию. При неуспешной текущей приёмке живую отправку заменяйте сохранённым показом. Полный прогон с речью и смоделированной задержкой ещё требуется; технический тест комплекта его не заменяет.
