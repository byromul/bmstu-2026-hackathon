# Диагностика доступа к Git и автоматической проверки

Проверено 2026-11-08 в текущей сессии подготовки лекции. Это локальное наблюдение, а не общее описание всех установок Codex.

## Установлено

- `.git/index.lock` отсутствует. Ошибка относится к попытке создать файл, а не к существующей блокировке.
- `.git` принадлежит текущему пользователю; обычные права каталога `drwxr-xr-x`, права индекса `-rw-r--r--`. Запрещающих ACL и флагов неизменяемости не обнаружено. Флаг `hidden` не запрещает запись.
- Эффективная политика текущей сессии допускает запись в рабочее дерево, но оставляет `.git` доступным только для чтения. `git status` работает; `git add` без расширенного разрешения получает `Operation not permitted` при создании `index.lock`.
- Проект остаётся `trusted`. В пользовательском `~/.codex/config.toml` включено `approvals_reviewer = "auto_review"`. Локального `.codex/config.toml` в репозитории нет.
- В журналах последняя видимая успешная WebSocket-сессия модели `codex-auto-review` для этого проекта — 15:22:32 по Москве. Позднее появляются повторные подключения, `sampling_error=request timed out` и `falling back to HTTP`; проверка разрешений не укладывается в срок.
- В тот же период daemon сообщает о тайм-аутах обновления каталога моделей; TUI — о тайм-аутах получения лимитов. Это указывает на проблему связи с сервисами Codex, а не на поломку Git или удаление разрешения пользователя.

## Границы вывода

Конкретный источник сетевого сбоя (маршрут, VPN, прокси, удалённый сервис) не установлен. Запущенный агентом `codex doctor --json` находится внутри песочницы с ограниченной сетью и доступом к процессам; его сетевые ошибки и сведения о запущенных процессах нельзя считать проверкой всей системы. Сообщения об ошибках доступа к SQLite в таком запуске также не доказывают повреждение базы.

Для дальнейшей проверки из обычного терминала:

```sh
codex doctor --network-only --summary
```

Команда существует в локальном Codex CLI 0.166.0; запуск вне песочницы агент не выполнял. Не требуется удалять отсутствующий lock-файл, менять права `.git` или отключать ограничения безопасности. Конфигурация, Git-индекс и фоновые процессы в ходе диагностики не изменялись.

Источники: эффективная политика сессии; `ls -ldeO@ . .git`; `ls -leO@ .git/index .git/index.lock`; чтение выбранных параметров конфигурации; журналы `~/.codex/logs_2.sqlite` (только чтение) и `~/.codex/app-server-daemon/daemon.stderr.log`; локальная справка `codex doctor --help`. Секреты и полные журналы в репозиторий не копировались.

Результат: **4 ok, 0 warn, 0 fail**; WebSocket подключился с HTTP 101, активные HTTP endpoints доступны. Затем успешно запущен `node assets/verify-deck.mjs` с отдельным временным Chrome. Ограничения `.git` внутри песочницы остаются прежними; восстановился механизм получения разрешения. Причина предшествовавшего сетевого сбоя не установлена.
